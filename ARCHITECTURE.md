# Architecture Overview

This project is an automated job search and application pipeline based on Python, CrewAI, SQLAlchemy, PostgreSQL, and Selenium.

## 1. System and Pipeline Overview

The end-to-end process consists of the following steps:
1. **Scraping**: Selenium bot scrapes LinkedIn for new job posts.
2. **Vacancy Review**: The `VacancyReviewCrew` processes the scraped posts, identifying valid job vacancies.
3. **Evaluation**: The `ResumeEvaluationCrew` checks the suitability of the vacancy based on candidates' skills.
4. **Resume Gen**: The `ResumeGenerationCrew` creates a customized resume for a suitable job.
5. **Email Gen**: The `EmailGenerationCrew` drafts an application email.
6. **Telegram / Email Submission**: The pipeline notifies via Telegram or applies via email automatically.

**Technology Stack:**
- Python
- CrewAI (LLM Orchestration)
- SQLAlchemy & Alembic (ORM & Migrations)
- PostgreSQL (Database)
- Selenium (Web Scraping)
- Ollama & OpenAI API (LLMs)
- Docker Compose (Containerization)

## 2. Codebase Structure

The source code is located in [`src/ljpa_reworked/`](src/ljpa_reworked/):

- `crews/`: Contains the configurations and logic for AI crews (`email_generation_crew`, `resume_evaluation_crew`, `resume_generation_crew`, `vacancy_review_crew`).
- `models/`: SQLAlchemy ORM models (`database_models.py`) and Pydantic schemas (`crewai_pydantic_models.py`).
- `operations/`: Contains business logic for interacting with the database and external environments.
- `services/`: External integrations (Selenium, Telegram, Email).
- `tools/`: Custom CrewAI tools utilized by the agents.
- `workflow.py` / `crew_workflow.py`: Orchestrates the overall task flow and execution pipeline.

## 3. Data Model & Database Schemas

The application uses PostgreSQL with SQLAlchemy for mapping tables.
Key entities include:
- **Vacancies**: Information about job postings.
- **Evaluations**: Assessment records generated by `ResumeEvaluationCrew`.
- **Generated Resumes/Emails**: Artifacts created by agents.
- **Logs**: Execution and scraping logs.

Alembic is used for database migrations. Any schema changes in `models/` must be followed by generating an alembic revision and applying it.

## 4. Environment & Docker Configuration

- **.env**: Environment variables like `OPENAI_API_KEY`, DB credentials, etc.
- **compose.yml**: Docker Compose file that spins up the application, Selenium grid/container, PostgreSQL, and Ollama.
- **Ollama**: Local container for LLMs for offline inference or privacy purposes.
